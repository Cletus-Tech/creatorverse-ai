# CreatorVerse — Website Blueprint
Version 1.0 | Planning baseline | 2026-11-11

## Public entry
The root URL opens a premium, minimal landing page. The first screen introduces CreatorVerse and exposes three primary divisions: Digital Skills, Academic and Campus Life. Do not turn the homepage into a dashboard or exhaustive sitemap.

## Main routes
- Home / brand introduction.
- Digital Skills → skills/course catalogue → course detail → enrolment/checkout → learning room.
- Academic → Secondary School / Tertiary Institutions.
- Secondary School → WAEC / NECO / JAMB / GCSE / other approved exams → subject → topic → practice/mock exam.
- Tertiary → institution → faculty → department/programme → level → semester → course (final model pending).
- Campus Life → Accommodation / Marketplace / Study Hub / Errands.
- Accommodation → Find a Roommate / Find an Apartment / Become an Agent / Accommodation Community.
- Community, profiles, posts, messages and notifications.
- Account/settings/privacy, help/support, authentication/recovery.
- Certificate verification.
- Super Admin Control Board.

## Homepage content order
1. Minimal header: logo, essential links and one clear account/action area.
2. Hero: concise positioning, primary action, secondary explore action and distinctive brand visual.
3. Three division entry points.
4. Short explanation of how CreatorVerse works.
5. Selected pathways/features from published content only.
6. Trust and safety.
7. Compact footer with legal/support links.

## Interaction rules
Every visible control works or is clearly marked unavailable/planned. Use real published content, honest empty/loading/error states. Never show fabricated reviews, user counts, prices, properties or match percentages.

## Account workspace
Role-aware dashboard and consistent global navigation. Mobile navigation must not collide with content or duplicate controls.

## Super Admin
One web console: overview, people/roles, brand/site content, skills/courses, academic, campus services, housing verification, moderation, payments, certificates, notifications, analytics, support, configuration and audit logs. High-risk actions require confirmation and audit history.

## Migration note
The current repository README describes a static website in public/. Next.js is a proposed target, not an existing implementation. Audit source, deployment, integrations and user data before choosing migration strategy.
